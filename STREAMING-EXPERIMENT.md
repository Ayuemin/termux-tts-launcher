# Потоковая озвучка — отдельный эксперимент

**Статус: эксперимент, не замена стабильной версии.** Стабильная ветка `main`, обычный APK «Озвучить» и команда `tts-launcher-play` не затрагиваются.

## Как устроено

Экспериментальное Android-приложение **«Озвучить Stream»** начинает собственный foreground service. Сервис запускает в Termux отдельный Python-обработчик `tts-launcher-stream` через RUN_COMMAND, затем системный Android MediaPlayer подключается к `http://127.0.0.1:<случайный порт>/stream/<случайный токен>`. Python отдаёт необработанные MP3-пакеты `edge_tts.Communicate(...).stream()` по HTTP chunked transfer encoding без записи аудиофайлов. Используется прежний голос `ru-RU-DmitryNeural`.

Пока **нельзя гарантировать**, что конкретная реализация Android MediaPlayer на TECNO/HiOS поддержит неизвестную длину MP3 по HTTP и начнёт воспроизведение до окончания потока. Именно это необходимо проверить на телефоне. Если устройство ждёт полного аудио или выдаёт ошибку, экспериментальная программа может не работать. Стабильная программа останется работоспособной.

## Установка на телефон

1. В обычном Termux установите **только дополнительный экспериментальный обработчик**:

```bash
cd ~/termux-tts-launcher
git fetch origin main feature/streaming-tts
git pull --ff-only origin main
bash termux/install-launcher.sh
git show origin/feature/streaming-tts:termux/tts-launcher-stream > "$PREFIX/bin/tts-launcher-stream"
chmod 755 "$PREFIX/bin/tts-launcher-stream"
```

2. Убедитесь, что установлен Termux, приложение Termux:API, а также разрешён `allow-external-apps=true` (см. README основной ветки). Для экспериментального сервера Termux:API не требуется, но существующую установку менять не нужно.
3. Из [GitHub Actions экспериментальной ветки](https://github.com/Ayuemin/termux-tts-launcher/actions/workflows/build-apk.yml?query=branch%3Afeature%2Fstreaming-tts) скачайте артефакт `termux-tts-stream-experimental-apk` и установите `streamapp-debug.apk`. Это **отдельное приложение**, исходный значок «Озвучить» остаётся прежним.
4. Для «Озвучить Stream» включите разрешение **Run commands in Termux environment** в настройках Android.
5. Скопируйте текст, нажмите «Озвучить Stream» и дождитесь звука. Повторное нажатие должно немедленно остановить плеер; можно также нажать «Остановить» в уведомлении.

Временных MP3 в этом варианте **нет**. При успешном получении аудиопакетов Python ведёт небольшой журнал с длительностями, без самого текста и без звука:

```bash
tail -n 30 ~/.cache/termux-tts-launcher-stream/last-events.log
```

### Возврат к стабильной версии

Откройте обычное приложение **«Озвучить»**. Оно и его скрипт `tts-launcher-play` оставались неизменными. Экспериментальное приложение можно удалить; дополнительный `tts-launcher-stream` можно оставить либо убрать вручную через `rm "$PREFIX/bin/tts-launcher-stream"`.

### Ограничения

- Внутренний HTTP-сервер слушает **только 127.0.0.1** и использует случайный токен на каждый запуск; доступ к Интернету используется только для Edge TTS. На телефоне стороннее приложение технически может пытаться обращаться к localhost, поэтому этот прототип не предназначен для конфиденциальных материалов.
- Android MediaPlayer поддерживает сетевые источники, но не гарантирована поддержка бесконечного chunked MP3-потока. При необходимости следующим шагом станет реализация собственного MP3-декодера на MediaCodec + AudioTrack, но для первого теста без тяжёлых зависимостей используем системный MediaPlayer.
- Текст передаётся Microsoft Edge TTS. Android foreground service отображает уведомление при активном воспроизведении.
- Заявленное сокращение задержки до 5–7 секунд — цель эксперимента, не гарантированный результат. Для теста используйте одинаковый текст и интернет-соединение.

### Исправление ошибки NoAudioReceived (14 октября 2026)

Если глобальная `edge-tts 7.2.8` перестала получать звук, обе программы используют локальную, подтверждённую тестом `7.3.1` в `~/.local/share/termux-tts-launcher/edge-tts-7.3.1/`. После установки скрипта из этой ветки отдельная потоковая версия обращается к новой библиотеке, не затрагивая другие Python-проекты. Стандартный APK и экспериментальный APK переустанавливать не требуется; обновляются только скрипты Termux.
