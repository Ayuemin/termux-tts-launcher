# Termux TTS Launcher — «Озвучить»

Маленькое приложение для Android и боковой панели TECNO/HiOS: **скопировать текст → нажать «Озвучить» → слушать голос Microsoft Edge TTS**. Termux открывать при каждом запуске не требуется.

- **Голос:** русский `ru-RU-DmitryNeural` (Microsoft Edge TTS).
- **Управление:** первое нажатие запускает чтение, второе останавливает, третье запускает снова (в том числе при подготовке звука).
- **Аудио:** только временные MP3 во внутреннем каталоге Termux, без файлов в «Загрузках».
- **Независимость:** существующая команда `tts` и другие TTS-проекты не изменяются.
- **Интернет обязателен:** текст передаётся сервису Microsoft для синтеза голоса. Не используйте эту озвучку для конфиденциальных текстов.

## Установка с нуля

### Шаг 1. Установить Termux и Termux:API

Для чистого Android рекомендуется установить **оба приложения из F-Droid**:

1. [Termux — F-Droid](https://f-droid.org/packages/com.termux/)
2. [Termux:API — F-Droid](https://f-droid.org/packages/com.termux.api/)

Можно установить APK с этих страниц напрямую или через приложение F-Droid. Откройте Termux хотя бы раз и дождитесь начальной настройки.

**Важно:** Termux и Termux:API должны быть **подписаны одним источником**. Не смешивайте Termux из GitHub и Termux:API из F-Droid: расширение может не работать из-за несовпадения подписей. Если Termux уже установлен и настроен, **не удаляйте его** — установите Termux:API из совместимого источника. Подробности: [официальная инструкция Termux](https://github.com/termux/termux-app#installation).

Нужен Android 8.0+ и доступ в интернет. Root, Termux:Widget, Chrome и FFmpeg не требуются.

### Шаг 2. Установить скрипт озвучки

Запустите **обычный Termux**, не Ubuntu/proot. Вставьте команды:

```bash
pkg update -y
pkg install -y git nano
cd ~
git clone https://github.com/Ayuemin/termux-tts-launcher.git
bash ~/termux-tts-launcher/termux/install-launcher.sh
```

Установщик добавит недостающие `python`, пакет `termux-api` и базовые зависимости `edge-tts`, затем **отдельно** установит проверенную `edge-tts 7.3.1` в `~/.local/share/termux-tts-launcher/edge-tts-7.3.1/` и команду `tts-launcher-play`. Существующая глобальная версия `edge-tts` не обновляется, а команда `tts` не заменяется.

Если репозиторий уже был клонирован, вместо `git clone` воспользуйтесь разделом [«Обновление»](#обновление).

### Шаг 3. Проверить озвучку в Termux

Убедитесь, что приложение **Termux:API** установлено, и выполните:

```bash
termux-media-player info
printf 'Привет. Проверка озвучки.' | tts-launcher-play
```

Ответ `No track currently!` на первую команду — нормален, когда музыка не играет. После второй команды при работающем интернете должна прозвучать тестовая фраза.

### Шаг 4. Разрешить внешние команды в Termux

Откройте файл настроек через текстовый редактор:

```bash
mkdir -p ~/.termux
nano ~/.termux/termux.properties
```

Найдите параметр `allow-external-apps` и установите:

```properties
allow-external-apps=true
```

Если параметра нет, добавьте строку в конец файла. Если есть `allow-external-apps=false`, **замените**, а не дублируйте её.

Сохранить в nano: **Ctrl+O → Enter → Ctrl+X**. Затем:

```bash
termux-reload-settings
```

При необходимости закройте и вновь откройте Termux. Не вводите `~/.termux/termux.properties` как команду: это файл настроек, а не исполняемая программа.

**Безопасность:** `allow-external-apps=true` позволяет приложениям с выданным Android-разрешением `RUN_COMMAND` запускать команды Termux. Выдавайте это разрешение только доверенным приложениям. [Официальная документация RUN_COMMAND](https://github.com/termux/termux-app/wiki/RUN_COMMAND-Intent).

### Шаг 5. Установить приложение «Озвучить»

1. Откройте [GitHub Actions — Build Android APK](https://github.com/Ayuemin/termux-tts-launcher/actions/workflows/build-apk.yml).
2. Откройте последний **успешный** запуск (**зелёная отметка**).
3. В разделе **Artifacts** скачайте `termux-tts-launcher-debug-apk`, извлеките из ZIP файл `app-debug.apk`.
4. Установите APK на телефон. При необходимости разрешите установку APK из браузера/файлового менеджера.
5. Android → **Приложения → Озвучить → Разрешения → Дополнительные разрешения**: включите **Run commands in Termux environment** («Запуск команд в среде Termux»). Названия пунктов различаются между версиями Android. Разрешение также может запрашиваться при первом открытии «Озвучить».

Если обновление APK поверх существующего запрещено из-за **несовпадения подписи**, удалите только приложение **«Озвучить»**, затем установите новый APK. **Не удаляйте Termux и Termux:API.** APK из Actions — отладочная сборка, не релиз для магазина.

### Шаг 6. Добавить в боковую панель TECNO/HiOS

Добавьте обычное приложение **«Озвучить»** в Smart Panel. Скопируйте текст в любом приложении, нажмите значок и дождитесь речи. Повторное нажатие **останавливает**, следующее — запускает новую озвучку.

Лаунчер кратковременно появляется на переднем плане, читает буфер и передаёт текст в Termux через официальный `RUN_COMMAND`. После этого исходное приложение снова оказывается на экране.

## Обновление

### Обновить Python-скрипт без переустановки APK

В Termux:

```bash
cd ~/termux-tts-launcher
git pull --ff-only origin main
bash termux/install-launcher.sh
```

Проверить текущий коммит:

```bash
git -C ~/termux-tts-launcher log -1 --oneline
```

**Изменения скрипта не устанавливаются автоматически вместе с APK.** Если обновился только `termux/tts-launcher-play`, достаточно команд выше. Новый APK нужен только при изменениях Android-приложения.

## Диагностика и файлы на телефоне

### Где хранится звук и удаляется ли он?

MP3 генерируются во **временных папках** Termux (с префиксом `tts-launcher-`). При штатном завершении или обработанном исключении они удаляются автоматически. Если Android аварийно завершил Python-процесс, остатки могут остаться; при следующем запуске озвучки скрипт удаляет **свои временные папки старше 24 часов**. Новые папки и другие проекты не затрагиваются.

Ни в «Загрузках», ни в галерее озвучка файлы не сохраняет. Файлы других команд TTS не меняет.

### Накапливаются ли статистика и журналы?

**Бесконечного накопления нет.** В `~/.cache/termux-tts-launcher/` используются:

| Файл | Для чего | Ограничение |
| --- | --- | --- |
| `last-timing.txt` | Только **последний успешный замер** задержки | Каждый следующий замер **перезаписывает** файл |
| `last-events.log` | Короткие служебные события запуска/остановки и ошибок | Автоматически **очищается** при превышении 16 КБ |
| `active` | Маркер активной озвучки | Удаляется после штатного завершения; иногда сохраняется для безопасной остановки после сбоя |
| `active.lock` | Маленький файл синхронизации | Не разрастается |

Текст буфера обмена и аудиоданные **в статистику не записываются**. Диагностика не отправляется разработчику и доступна только локально.

Проверка времени ожидания первого MP3-пакета:

```bash
cat ~/.cache/termux-tts-launcher/last-timing.txt
```

Важные показатели (миллисекунды от запуска Python):

- `first_stream_request_ms` — обращение к Edge TTS после загрузки библиотеки;
- `first_audio_packet_ms` — получение **первого** MP3-пакета;
- `first_synthesis_done_ms` — полный первый фрагмент готов;
- `first_audio_ready_ms` — фрагмент доступен для проигрывания;
- `first_play_request_ms` — подтверждение запуска команды плеера;
- `player_command_ms` — время выполнения команды плееру;
- `first_attempt_number` — номер попытки.

Время запуска Termux до выполнения Python не входит в эти показатели. Это **не** измерение момента, когда пользователь фактически услышал звук.

Последние события:

```bash
tail -n 25 ~/.cache/termux-tts-launcher/last-events.log
```

Если журналы больше не нужны, их можно удалить **при остановленной озвучке**:

```bash
rm -f ~/.cache/termux-tts-launcher/last-timing.txt ~/.cache/termux-tts-launcher/last-events.log
```

Они снова создадутся по мере работы, но останутся ограниченными по объёму.


### Исправление ошибки `NoAudioReceived` после изменения Microsoft

13 октября 2026 года в `edge-tts 7.3.0/7.3.1` был обновлён механизм токенов Microsoft. Старая версия `7.2.8` может перестать получать звук, даже если `termux-media-player` исправен.

Для **изолированного исправления** обычной озвучки:

```bash
cd ~/termux-tts-launcher
git pull --ff-only origin main
bash termux/install-launcher.sh
```

Установщик проверяет локальную версию и скачивает её только при необходимости. Другие Python-проекты и глобально установленную `edge-tts` он не обновляет. После обновления повтори запуск «Озвучить» и проверь журнал. Если в окружении изменятся несовместимые базовые зависимости `aiohttp` и других пакетов, нужно будет отдельно разбирать их версии.

## Если возникли проблемы

- **`RunCommandService requires allow-external-apps`**: повторите шаг 4 и перезапустите Termux.
- **Озвучка не запускается из значка**: проверьте разрешение `RUN_COMMAND` у приложения «Озвучить», а также шаг 3 (звук напрямую в Termux).
- **`termux-media-player info` не работает**: установите приложение Termux:API из того же источника, что Termux; запустите `pkg install termux-api`.
- **Снова начинается чтение после второго нажатия**: обновите скрипт по разделу «Обновление» и проверьте `last-events.log`.
- **Озвучка начинается с большой задержкой**: сравните сеть/VPN и проверьте `last-timing.txt`; время зависит от подключения к Microsoft.
- **Прерывается фоновая работа**: в настройках батареи Android/HiOS разрешите фоновую работу Termux и Termux:API.
- **`git clone` сообщает `destination path ... already exists`**: проект уже скачан — примените команды из «Обновления».

## Ограничения и устройство проекта

- Необходим интернет, поскольку синтез выполняет Microsoft. Для секретных текстов такая схема не подходит.
- Максимальный объём текста — **96 КиБ в UTF-8**; превышение не обрезается молча.
- Синтез идёт параллельно максимум двумя задачами. Первый фрагмент — до 155 символов, последующие — до 650.
- Пока используются готовые MP3-фрагменты и `termux-media-player`, а не потоковое воспроизведение. Переход на потоковое аудио — отдельный эксперимент.
- Termux:API предоставляет общий медиаплеер; другой вызов `termux-media-player play` может прервать наш текущий файл.
- `android/` — минимальный Android-лаунчер; `termux/` — Python-скрипт и установщик; `tests/` — проверки; `.github/workflows/` — сборка и тесты.
